First login

Status: Updated Audience: Administrator

Use this page after the server installation is complete and the DNA-Nexus web interface is reachable. The first administrator bootstrap depends on the login method selected during installation: QR / DNA Connect, OPAQUE zero-knowledge password, or traditional username and password.

Open the login page

Open the DNA-Nexus server address in a browser. The address depends on the installation choices: it may be the local server address, a public hostname, a reverse proxy address or a Cloudflare Tunnel hostname.

Example: If the installer showed an access URL at the end of installation, use that URL to open the DNA-Nexus login page.

Choose the login method

DNA-Nexus can show different login screens depending on the authentication method selected during installation. The examples below show the English login screens.

Username and password

Use this login screen when DNA-Nexus is configured for traditional username and password login.

QR / DNA Connect

Use this login screen when DNA-Nexus is configured for QR-based DNA Connect login. The user scans the QR code with a trusted DNA-Nexus compatible device.

OPAQUE zero-knowledge password

Use this login screen when DNA-Nexus is configured for OPAQUE zero-knowledge password login.

First administrator bootstrap

A fresh DNA-Nexus installation needs exactly one initial administrator before normal user management can begin. The bootstrap mechanism depends on the browser login method selected during installation.

Important: Only a trusted person should perform the first administrator bootstrap. After an enabled administrator exists, later users are not automatically promoted.
Login method How first admin is created When to use it
QR / DNA Connect The first successfully verified DNA Connect identity becomes the initial admin. Best for owner/admin setups where the admin uses a trusted DNA-Nexus compatible device.
OPAQUE The installer or server admin enables a one-time OPAQUE bootstrap token. The browser performs OPAQUE registration and the server creates the first admin. Best when the installation should use zero-knowledge password login from the beginning.
Username/password The installer or server admin enables a one-time password bootstrap token and calls the password bootstrap endpoint. Best for traditional business/customer installations where users expect email + password login.

Method 1: QR / DNA Connect bootstrap

In QR / DNA Connect mode, the browser shows a QR code. The first trusted identity that successfully verifies the login on a fresh server becomes the initial administrator.

  1. Open the login page

    Open the DNA-Nexus server URL in a browser.

  2. Scan the QR code

    Use DNA Connect or a compatible trusted device to approve the login.

  3. Confirm admin access

    After the login completes, open the Admin area from the sidebar. The first verified identity is now the initial administrator.

Note: QR bootstrap is the only first-admin method where the first successful browser login itself can create the initial administrator. Password and OPAQUE installs use explicit bootstrap tokens instead.

Method 2: OPAQUE bootstrap

OPAQUE mode uses a zero-knowledge password flow. The plaintext password must not be sent to the server. Because there is no admin yet on a fresh installation, OPAQUE first-admin setup uses a temporary bootstrap token.

  1. Enable OPAQUE login mode

    The server must run with OPAQUE browser login enabled.

    PQNAS_LOGIN_MODE=opaque

  2. Set a temporary OPAQUE bootstrap token

    The installer may create this automatically. If doing it manually, set a strong random token only for the bootstrap window. 

    PQNAS_OPAQUE_BOOTSTRAP_TOKEN=<temporary-random-token>

  3. Open the OPAQUE bootstrap/setup page

    Complete the OPAQUE setup in the browser. The browser performs the OPAQUE cryptographic registration steps locally; the server stores only the OPAQUE credential record.

  4. Save the recovery words

    If a new admin identity is created, DNA-Nexus shows 24 recovery words once. Store them safely. They are not stored by the server and cannot be shown again.

  5. Remove the bootstrap token

    After the first admin exists, remove the temporary token and restart the service.

Method 3: Username/password bootstrap

Traditional username/password mode uses an explicit one-time bootstrap endpoint. A normal password login attempt must not create users by itself. This prevents unknown visitors from creating accounts from the public login page.

  1. Enable password login mode

    The server must run with password login enabled.

    PQNAS_LOGIN_MODE=password

  2. Set a temporary password bootstrap token

    The installer may create this automatically. If doing it manually, generate a strong random token and keep it only until the first admin is created. 

    PQNAS_PASSWORD_BOOTSTRAP_TOKEN=<temporary-random-token>

  3. Create the first admin from the server

    Run the bootstrap request locally on the server. Localhost is recommended during bootstrap so that a public proxy, tunnel or cached route cannot point to the wrong backend. 

    curl -sS \
  -H "Content-Type: application/json" \
  -H "X-PQNAS-Bootstrap-Token: $token" \
  -d '{"login":"admin@example.com","name":"Admin","password":"change-this-long-password"}' \
  http://127.0.0.1:8081/api/auth/password/bootstrap-admin

  4. Save the recovery words

    If the endpoint creates a new admin identity, it returns 24 recovery words once. Save them immediately. The server does not store the words.

  5. Log in normally

    After the bootstrap succeeds, open the public DNA-Nexus login page and sign in with the admin email and password.

Remove bootstrap tokens

Bootstrap tokens are temporary installation helpers. They must not remain configured after the first administrator has been created. 

# Password bootstrap cleanup example
sudo sed -i '/^PQNAS_PASSWORD_BOOTSTRAP_TOKEN=/d' /etc/pqnas/pqnas.env
sudo systemctl restart pqnas.service
# OPAQUE bootstrap cleanup example
sudo sed -i '/^PQNAS_OPAQUE_BOOTSTRAP_TOKEN=/d' /etc/pqnas/pqnas.env
sudo systemctl restart pqnas.service
Do not leave bootstrap tokens enabled. After bootstrap, all new users should be created or approved through the Admin area.

Bootstrap troubleshooting

Error or symptom Meaning What to check
password_auth_disabled The request reached a server process that is not in password login mode. Check /api/auth/config and confirm PQNAS_LOGIN_MODE=password.
bootstrap_disabled Password mode is enabled, but no password bootstrap token is configured. Set PQNAS_PASSWORD_BOOTSTRAP_TOKEN temporarily.
bootstrap_denied The supplied bootstrap token is missing or does not match. Use the exact token from the server environment.
enabled_admin_exists A first admin already exists. Use the existing admin account, or reset users intentionally before testing bootstrap again.
Localhost works but public URL behaves differently The public proxy, tunnel or hostname may be pointing to a different backend state. Compare http://127.0.0.1:8081/api/auth/config with the public /api/auth/config.

After login

  1. Confirm that the dashboard opens

    After login, confirm that the DNA-Nexus dashboard or main application view opens normally.

  2. Open the administration area

    After the first administrator login, the DNA-Nexus workspace may still look empty. This is expected on a new installation.

    Before creating normal users or uploading content, open the Admin area from the left sidebar. The Admin area is used for the initial server setup, user management, approvals, storage settings and other administrator tasks.

  3. Check users and approvals

    Open the user administration or approvals page and confirm whether any new identities are waiting for approval.

  4. Continue initial setup

    After the first login works, continue with server settings, user creation and storage allocation.
